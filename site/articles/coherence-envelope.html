Inside the coherence envelope.

A working vocabulary for the gap between a published value and a value someone actually reads.

MCMaya ChenOct 08, 20265 min read

Give the interval a name

We use coherence envelope as a working term for the interval between publishing a value and every participating reader observing it. The phrase is a local design label. The HTTP references listed here do not define it as a protocol term.

The interval can contain several independent lifetimes: an intermediary’s freshness window, a browser’s stored representation, and an application’s in-memory value. A single request trace may reveal only one of them. It is therefore useful to draw the boundaries before assigning a number.

What the headers can establish

max-age defines a freshness lifetime. s-maxage applies to shared caches and overrides max-age there. Neither header proves that every application replica has observed an origin update. The origin itself may still be reading an earlier state.

Avoid a number without a boundary

A claim such as “the envelope is sixty seconds” needs a starting event, an ending observation, and a population of readers. Without those, the number combines a policy setting with an unmeasured operational outcome.

This article supplies a vocabulary and a decomposition, not a measured result. For an example of a report that lacks enough evidence for a global conclusion, read the regional latency notebook.
