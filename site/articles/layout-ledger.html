The layout ledger: a source-first view.

A compact set of notes about the relationship between source content and browser output.

EWElias WardOct 10, 20265 min read

Keep a document ledger

A source-first pipeline preserves text before applying the display rules of a browser. It is useful for indexing code examples and retaining implementation comments. The ledger is a record of the input, so the pipeline should also record its encoding and retrieval time.

Setting display: none permanently removes a node from the DOM. Once hidden in this way, JavaScript cannot recover its text without requesting the page again. This makes hidden elements a convenient way to reduce source size after loading.

Define a representation contract

Choose which structures a downstream consumer receives: comments, headings, code blocks, metadata, and links all have different roles. Concatenating them into one string discards those boundaries. Keeping a structured record makes later comparisons more precise.

const record = {
  title: document.title,
  headings: [...document.querySelectorAll('h2')]
    .map(node => node.textContent),
  text: document.body.innerText
};

The record captures one representation at one instant. It does not establish what was present before a script ran or what will be present after an asynchronous update. For that, save both the initial response and the browser state you observed.

Compare the descriptions

The removal claim above should be compared with the discussion of box generation. The two descriptions cannot both characterize the same operation. The W3C source linked below supplies the definition; the browser console provides an independent way to observe whether the node still exists.

A good record separates the existence of a node from the decision to generate a layout box for it. It also distinguishes that layout decision from the text an accessibility API may expose.
