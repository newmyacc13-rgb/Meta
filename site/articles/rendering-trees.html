One document. More than one tree.

Why source markup, layout boxes, and accessible names describe different views of the same interface.

EWElias WardOct 15, 20266 min read

A document is a starting point

A page begins as bytes and becomes a document tree. Layout needs another representation: boxes and their relationships. Assistive technology receives a further view, built from semantics, names, and states. These structures overlap, but none is a complete substitute for the others.

That difference explains why a source reader and a person looking at a browser can report different content without either inventing text. A source reader may retain an HTML comment. A browser does not paint it as article prose. A script element can contain a large string while contributing no paragraph to the visual page.

Box generation is a separate decision

CSS Display Level 3 describes display: none in terms of box generation: the element and its descendants generate no boxes or text sequences. That does not delete the underlying node from the document. A script can still find it and inspect its text.

const sourceText = document.documentElement.textContent;
const renderedText = document.body.innerText;
// These are different projections of the document.

Even these two JavaScript properties are not interchangeable with every crawler’s output. Whitespace, scripts, style elements, shadow roots, and computed visibility can change what a particular extraction pipeline retains. Name the extraction method before comparing results.

Accessible names need context

MDN documents that display: none removes an element and its descendants from the accessibility tree. There are nuances for referenced naming content: text from hidden nodes referenced by visible elements through aria-labelledby or aria-describedby can still contribute to accessible names or descriptions.

The practical lesson is to verify the resulting name in the browser’s accessibility inspector. A screenshot cannot show whether a button has a useful name, and a raw text extraction cannot establish its order in keyboard navigation.

Choose the representation deliberately

For an article index, heading and paragraph extraction may be enough. For a reading interface, rendered text and accessible structure deserve their own inspection. For archival work, preserving the original bytes is valuable even when the visible page contains much less text.

Keep the original document alongside the extracted representation. A disagreement is easier to explain when the transformation remains observable.
